# 设计文档（中文）

## 1. 设计目标
- 提供清晰、可用的线路规划交互：选起点/终点 → 一键规划 → 地图与列表同步展示
- 算法与数据解耦：支持从 `edges.csv` 明确定义道路/连接关系，也支持按经纬度自动生成边作为兜底
- 可部署、可复现：`docker compose up -d --build` 一键运行

## 2. API 设计

### 2.1 健康检查
- `GET /api/health`
- 返回：`{ status: "ok", time: "..." }`

### 2.2 节点列表
- `GET /api/nodes`
- 返回：节点数组 `[{ id, name, lat, lng, type?, desc? }, ...]`

### 2.3 路径规划（支持路线策略）
- `GET /api/path?from=<id>&to=<id>[&strategy=<key>]`
- `strategy` 可选，缺省为 `shortest`（保持原有最短路行为）；非法值返回 400 中文错误
- 策略一览：
  - `shortest`：最短距离（默认，按地理距离）
  - `fastest`：省时间（最小化预计耗时：距离/速度 + 爬升与换乘惩罚）
  - `less-climb`：少爬坡（距离 + 爬升惩罚）
  - `less-transfer`：少换乘（距离 + 换乘惩罚）
  - `photo`：适合拍照（距离 - 景色奖励，权重设下限保证非负）
- 成功返回：
  - `startId` / `endId`
  - `totalDistanceMeters`
  - `pathNodeIds` / `pathNodes`
  - `segmentDistanceMeters`
  - `strategy` / `strategyName`（策略 key 与中文名）
  - `totalTimeMinutes`（估算总耗时）
  - `totalClimbMeters` / `totalTransfers`（总爬升 / 总换乘）
- 失败返回：`{ error: "...中文错误信息..." }`

## 3. 前端交互设计

### 3.1 控制面板
- 起点/终点下拉选择（支持搜索）
- 路线策略切换（最短距离 / 省时间 / 少爬坡 / 少换乘 / 适合拍照），已有结果时切换立即重算
- 交换起终点、清空选择
- 一键规划并展示策略名、总耗时、总距离、爬升/换乘统计与经过景点列表

### 3.2 地图交互
- 渲染所有景点 Marker
- Marker Popup 支持“一键设为起点/终点”
- 规划成功后绘制路线 Polyline

## 4. 数据与容错设计

### 4.1 CSV 数据
- `nodes.csv`：必须存在且包含列 `id,name,lat,lng`（其他列可选）
- `edges.csv`：可选；至少包含 `from,to`；权重列支持：`distance_meters` / `weight_meters` / `distanceMeters` / `weightMeters`
- `edges.csv` 策略属性列（可选，缺省为 0）：`climb_meters`（爬升）、`transfers`（换乘次数）、`scenic_score`（景色评分 0-10）

### 4.2 路线策略实现
- Dijkstra 主流程唯一，策略仅替换边权函数（`GraphService.strategyWeight`），保证策略切换不影响基础最短路逻辑
- 所有策略权重均非负（拍照策略设权重下限），满足 Dijkstra 前提
- 耗时/爬升/换乘等统计按路径实际经过的边累计，`totalDistanceMeters` 始终为真实地理距离
- 权重系数（速度、爬升/换乘惩罚、景色奖励等）可通过环境变量调整

### 4.2 容错策略
- 后端：`DataLoader` 对缺列/坏行进行跳过或给出明确的中文异常提示
- 前端：对节点 API 返回进行结构校验与清洗，避免脏数据触发运行时崩溃
- UI：ErrorBoundary 捕获不可预期异常并提示刷新重试

## 5. 性能与扩展
- 节点数量较小（景点级别）时，Dijkstra 在内存中运行即可满足交互性能
- 未来扩展点：
  - 引入真实道路网（大量边）时，可考虑启发式算法（A*）或预计算缓存
  - 为边增加更多权重维度（拥堵、票价、偏好等）
