# 设计文档（中文）

## 1. 设计目标
- 提供清晰、可用的线路规划交互：选起点/终点 → 一键规划 → 地图与列表同步展示
- 算法与数据解耦：支持从 `edges.csv` 明确定义道路/连接关系，也支持按经纬度自动生成边作为兜底
- 可部署、可复现：`docker compose up -d --build` 一键运行

## 2. API 设计

### 2.1 健康检查
- `GET /api/health`
- 返回：`{ status: "ok", time: "..." }`

### 2.2 节点列表
- `GET /api/nodes`
- 返回：节点数组 `[{ id, name, lat, lng, type?, desc? }, ...]`

### 2.3 最短路径（支持路线策略）
- `GET /api/path?from=<id>&to=<id>&strategy=<code>`（`strategy` 可选，默认 `shortest`）
- 策略取值：
  - `shortest`：距离最短（默认，边权 = 距离，保持原有行为）
  - `fastest`：省时间（边权 = 通行时间）
  - `least_climb`：少爬坡（边权 = 爬升×40 + 距离）
  - `fewest_transfers`：少换乘（边权 = 换乘×10000 + 距离）
  - `photo`：适合拍照（边权 = 距离 ÷ (1 + 0.2×两端拍照指数均值)）
- 所有策略权重均非负，复用同一个 Dijkstra 实现，仅权重函数不同
- 成功返回：
  - `startId` / `endId`
  - `totalDistanceMeters`
  - `pathNodeIds` / `pathNodes`
  - `segmentDistanceMeters`
  - `strategy` / `strategyLabel`（策略代码与中文名）
  - `totalTimeMinutes` / `totalClimbMeters` / `totalTransfers`（沿路径累计的耗时/爬升/换乘）
- 失败返回：`{ error: "...中文错误信息..." }`（未知策略返回 400）

## 3. 前端交互设计

### 3.1 控制面板
- 起点/终点下拉选择（支持搜索）
- 路线策略选择：距离最短 / 省时间 / 少爬坡 / 少换乘 / 适合拍照；起终点齐全时切换策略自动重新规划
- 交换起终点、清空选择
- 一键规划并展示策略名、总耗时、总距离、累计爬升/换乘与经过景点列表

### 3.2 地图交互
- 渲染所有景点 Marker
- Marker Popup 支持“一键设为起点/终点”
- 规划成功后绘制路线 Polyline

## 4. 数据与容错设计

### 4.1 CSV 数据
- `nodes.csv`：必须存在且包含列 `id,name,lat,lng`（其他列可选）；可选列 `photo_score`（0-10 拍照指数，供"适合拍照"策略使用）
- `edges.csv`：可选；至少包含 `from,to`；权重列支持：`distance_meters` / `weight_meters` / `distanceMeters` / `weightMeters`；策略数据列（均可选，缺失时按距离估算或取 0）：`time_minutes`、`climb_meters`、`transfers`

### 4.2 容错策略
- 后端：`DataLoader` 对缺列/坏行进行跳过或给出明确的中文异常提示
- 前端：对节点 API 返回进行结构校验与清洗，避免脏数据触发运行时崩溃
- UI：ErrorBoundary 捕获不可预期异常并提示刷新重试

## 5. 性能与扩展
- 节点数量较小（景点级别）时，Dijkstra 在内存中运行即可满足交互性能
- 未来扩展点：
  - 引入真实道路网（大量边）时，可考虑启发式算法（A*）或预计算缓存
  - 为边增加更多权重维度（拥堵、票价、偏好等）
